# @shopnetic/db

Prisma schema, the generated client, and the process-wide client singleton. One
schema file; models are grouped by bounded context and each context owns a
Postgres schema (`@@schema(...)`) — `plan/02-architecture.md` §5,
`plan/07-data-model.md`.

Evolution rules: **`plan/25-database-conventions.md`** — expand/contract
migrations, soft-delete by default, explicit FK behaviour, short transactions.

## Contexts present

| Schema     | Models                                                                                                                                                                              |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `identity` | `account`, `credential`, `email_verification`, `session`, `totp_secret`, `recovery_code`, `role`, `permission`, `role_permission`, `grant`, `staff_invite`, `audit_event`, `outbox` |

Other context schemas (`catalog`, `orders`, …) are added to the generator's
`schemas` list as their models land — Prisma rejects a schema with no models.

## Conventions in force

- **PK** `id` is a **v7 UUID generated by Prisma Client** (`@default(uuid(7))`).
  Postgres 16 has no native `uuidv7()`, and every write goes through the client,
  so there is no DB-side default — raw `INSERT`s must supply `id`.
- **Email** columns are `citext` (case-insensitive unique). The migration enables
  the `citext` extension.
- `audit_event` is append-only (no `updated_at`, never deleted). Monthly range
  partitioning is a later raw-SQL migration, once volume warrants it.
- `grant`'s natural-key unique index does **not** cover the all-`NULL` scope case
  (Postgres treats NULLs as distinct); writers de-dupe explicitly until Prisma
  supports `NULLS NOT DISTINCT`.
- A partial unique index on `account.email` `WHERE deleted_at IS NULL` is
  deferred until the account-erasure flow exists.

## Usage

```ts
import { getPrismaClient } from '@shopnetic/db';
const prisma = getPrismaClient(); // singleton; global-cached off-prod
```

`apps/api` wraps this in a Nest `PrismaService` (lifecycle + `ping()`).

## Creating the database

- **Docker Compose (default dev):** nothing to do — the `postgres` container
  creates the `shopnetic` database on first boot (`POSTGRES_DB` in
  `infra/docker/docker-compose.yml`).
- **Your own / a managed Postgres:** create it once first —
  `createdb shopnetic` (or `CREATE DATABASE shopnetic;`) — then point
  `DATABASE_URL` at it. `db:migrate` (dev) offers to create a missing database;
  `db:migrate:deploy` (CI/prod) does **not**.

The `identity` schema and all tables are created by the migration, not by hand.

## Commands

```bash
cp .env.example .env                         # DATABASE_URL → local Postgres (port 5433)

pnpm --filter @shopnetic/db generate         # prisma generate (also runs via turbo)
pnpm --filter @shopnetic/db db:migrate       # create + apply a dev migration
pnpm --filter @shopnetic/db db:migrate:deploy # apply pending migrations (CI/prod)
pnpm --filter @shopnetic/db db:seed          # permissions + system roles + role wiring (+ optional bootstrap Super Admin)
pnpm --filter @shopnetic/db db:studio        # Prisma Studio
pnpm --filter @shopnetic/db db:reset         # drop, re-migrate, re-seed
```

The seed is **idempotent** and, for system roles, authoritative — a
`role_permission` row not in `@shopnetic/auth`'s `ROLE_PERMISSIONS` is removed.

### Env

| Var                             | Required | Purpose                                                                    |
| ------------------------------- | -------- | -------------------------------------------------------------------------- |
| `DATABASE_URL`                  | yes      | Postgres connection string                                                 |
| `DIRECT_URL`                    | no       | un-pooled URL for `migrate` (falls back to `DATABASE_URL`)                 |
| `BOOTSTRAP_SUPERADMIN_EMAIL`    | no\*     | seed a first staff Super Admin (`account` + `credential` + global `grant`) |
| `BOOTSTRAP_SUPERADMIN_PASSWORD` | no\*     | min length 12                                                              |

\* set both or neither.
